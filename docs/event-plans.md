# Event plans and visualiser guidance

A customer can keep up to 12 named events in their existing private wedding workspace. Ceremony, reception, party and other event types are available. Each has a validated brief, a basket with item-specific hire periods, private photo IDs and its latest successful render ID. Boards and saved inspiration remain account-wide.

The active brief is mirrored in the original top-level brief for compatibility. Existing workspaces become a Wedding day plan on their next explicit save. Switching or creating an event first saves the outgoing snapshot using the existing workspace revision check. The screen changes only after successful persistence. A failed save keeps the original plan open. Event switching is disabled during generation and checkout.

Dates, baskets and render references are restored per event; original photos and renders are checked against the signed-in account on every save. Signed photo URLs are never stored in event snapshots. Pricing, stock, supplier lead times and hire periods are still validated by the order endpoint. Order notes include the event name. Each event basket is submitted separately.

The countdown uses calendar dates in Europe/London, including the daylight-saving transition. Dates can remain undecided for browsing, with a prompt to add a date before relying on availability.

Visualiser images use object-contain within one inset frame. The completion prompt is below the image. Accuracy notices explain that generated images can change scale, layout, colours, quantities and product details; supplier photos and specifications take precedence. Delivery guidance asks customers to request in good time and agree arrival deadlines. These notices do not exclude statutory rights.

Google Photos and Pinterest guides are always expanded. Google Photos remains a manual download/upload workflow. Pinterest public previews remain optional, with external opening for private boards. Neither imports a library automatically or grants new account access.
